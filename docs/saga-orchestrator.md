# SagaOrchestrator

The `SagaOrchestrator` is a core component of the saga pattern implementation in this CQRS/Event Sourcing system. It acts as the central dispatcher that routes incoming domain events to all registered saga handlers, manages the lifecycle of sagas, and ensures that events produced by sagas (outbox events) are published to the event bus.

## Role in the Saga Pattern

In distributed systems, a saga is a sequence of local transactions where each transaction updates the database and publishes a message or event to trigger the next transaction step. If a step fails, the saga executes compensating transactions to undo the preceding steps.

The `SagaOrchestrator` implements the **orchestration** style of saga pattern:
- It receives domain events from the event bus
- It determines which saga handlers are interested in each event
- It dispatches events to all capable handlers
- It collects and publishes any new events generated by saga processing (outbox pattern)
- It logs saga lifecycle transitions for monitoring and debugging

Saga handlers themselves (`ISagaHandler<TSaga, TEvent>`) contain the business logic for processing specific events and updating saga state. The orchestrator decouples event routing from saga logic.

## Public API

### Constructor

```csharp
public SagaOrchestrator(
    IEnumerable<ISagaHandlerWrapper> handlers,
    IEventBus eventBus,
    ILogger<SagaOrchestrator> logger)
```

**Parameters:**
- `handlers`: Collection of saga handler wrappers that can process domain events
- `eventBus`: Used to publish outbox events generated by saga handlers
- `logger`: For logging saga dispatch activities and errors

All parameters are validated via `GuardClauses.NotNull` and will throw `ArgumentNullException` if null.

### DispatchAsync Method

```csharp
public async Task<Result> DispatchAsync(
    DomainEvent @event, 
    CancellationToken cancellationToken = default)
```

**Parameters:**
- `@event`: The domain event to dispatch to saga handlers
- `cancellationToken`: Optional token to cancel the operation

**Returns:**
- `Result.Success()` if no handlers could process the event or all handlers succeeded
- `Result.Failure("SAGA_DISPATCH_ERROR", errorMessage)` if any handler failed, containing semicolon-separated error messages

**Behavior:**
1. Throws `ArgumentNullException` if `@event` is null
2. Finds all handlers where `CanHandle(@event)` returns true
3. If no capable handlers, returns success immediately
4. For each capable handler:
   - Calls `HandleAsync` to process the event
   - If handler returns failure, logs error and collects error message
   - Drains and publishes any outbox events produced by the handler via `_eventBus.PublishEventAsync`
   - If handler throws exception, logs full exception and collects error message
5. Returns success if all handlers succeeded, otherwise returns failure with collected errors

**Thread Safety:** This method is safe for concurrent calls as it only reads from immutable collections and dependencies.

## Related Types

### ISagaHandlerWrapper

Non-generic interface that abstracts saga handlers to prevent generic type proliferation in the orchestrator:

```csharp
public interface ISagaHandlerWrapper
{
    bool CanHandle(DomainEvent @event);
    Task<Result> HandleAsync(DomainEvent @event, CancellationToken cancellationToken = default);
    IReadOnlyList<DomainEvent> DrainOutboxEvents();
}
```

### SagaHandlerWrapper<TSaga, TEvent>

Generic adapter that bridges strongly-typed saga handlers to the wrapper contract:

```csharp
public sealed class SagaHandlerWrapper<TSaga, TEvent> : ISagaHandlerWrapper
    where TSaga : SagaBase
    where TEvent : DomainEvent
```

**Responsibilities:**
- Wraps an `ISagaHandler<TSaga, TEvent>`
- Implements `CanHandle` by checking if the incoming event is of type `TEvent`
- Calls the inner handler's `HandleAsync` method with proper type casting
- Collects outbox events produced by the inner handler in `_latestOutbox`
- Provides `DrainOutboxEvents` to return and clear collected events

## Usage Example

### Registering Saga Handlers

In your application's DI container registration (e.g., `Program.cs`):

```csharp
// Register saga handlers as wrappers
builder.Services.AddScoped<ISagaHandlerWrapper, SagaHandlerWrapper<OrderSaga, OrderCreated>>();
builder.Services.AddScoped<ISagaHandlerWrapper, SagaHandlerWrapper<OrderSaga, OrderPaid>>();
builder.Services.AddScoped<ISagaHandlerWrapper, SagaHandlerWrapper<OrderSaga, OrderShipped>>();

// Register the orchestrator
builder.Services.AddScoped<SagaOrchestrator>();
```

### Event Bus Subscription

Subscribe the orchestrator to receive domain events:

```csharp
// Assuming you have access to the event bus and orchestrator
eventBus.Subscribe<DomainEvent>(orchestrator.DispatchAsync);
```

### Custom Saga Handler Implementation

```csharp
public class OrderSaga : SagaBase
{
    public OrderState State { get; private set; } = new();
    
    // Other saga state and methods...
}

public interface ISagaHandler<TSaga, TEvent> where TSaga : SagaBase
{
    Task<Result> HandleAsync(TEvent @event, CancellationToken cancellationToken = default);
}

public class OrderSagaHandler : 
    ISagaHandler<OrderSaga, OrderCreated>,
    ISagaHandler<OrderSaga, OrderPaid>,
    ISagaHandler<OrderSaga, OrderShipped>
{
    private readonly IOrderRepository _repository;
    
    public OrderSagaHandler(IOrderRepository repository)
    {
        _repository = repository;
    }
    
    public async Task<Result> HandleAsync(OrderCreated @event, CancellationToken cancellationToken = default)
    {
        // Load or create saga instance
        var saga = await _repository.GetByIdAsync(@event.OrderId) ?? new OrderSaga();
        
        // Process event and update state
        saga.State = OrderState.Created;
        
        // Produce outbox event (e.g., for reservation step)
        saga.OutboxEvents.Add(new ReserveInventory(@event.OrderId, @event.Items));
        
        await _repository.SaveAsync(saga, cancellationToken);
        return Result.Success();
    }
    
    // Implement HandleAsync for OrderPaid and OrderShipped similarly...
}
```

## Important Notes

1. **Outbox Pattern**: The orchestrator implements the outbox pattern to ensure reliable event publishing. Events produced by sagas are temporarily stored and published after successful event handling, preventing dual-write problems.

2. **Error Handling**: If any saga handler fails, the orchestrator continues processing other capable handlers but returns a failure result. Individual handlers should implement their own compensation logic if needed.

3. **Idempotency**: Saga handlers should be designed to handle duplicate events idempotently, as the event bus may deliver the same event multiple times.

4. **Lifecycle**: Sagas are typically loaded from and saved to a repository by their handlers. The orchestrator does not manage saga persistence directly.

5. **Logging**: The orchestrator logs:
   - Information: When dispatching events to handlers
   - Error: When a handler fails or throws an exception
   These logs are essential for monitoring saga execution in production.
